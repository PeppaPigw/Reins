<objective>
Implement snapshot integrity validation with auto-rebuild and journal compaction with configurable retention policy.

Purpose: Snapshots currently load without any integrity check — a corrupted file silently produces wrong state. Journal files grow unbounded. This plan adds tamper detection + self-healing for snapshots, and storage management for journals.

Output: SnapshotStore validates integrity on every load and rebuilds from journal on failure. Journal compaction reduces storage while preserving full replay capability within the retention window.
</objective>

    1. Create `src/reins/kernel/event/compaction.py`:
       - Imports: `json`, `asyncio`, `os`, `from dataclasses import dataclass, field`, `from pathlib import Path`, `import aiofiles`, `from reins.kernel.event.envelope import event_from_dict, event_to_dict`, `from reins.kernel.event.journal import EventJournal`, `from reins.kernel.snapshot.store import SnapshotStore`

       - Dataclass `RetentionPolicy`:
         - `max_events: int = 10_000` — compact when journal exceeds this count
         - `keep_last_n: int = 1_000` — always keep the most recent N events
         - `keep_after_snapshot: bool = True` — keep all events after the last snapshot's event_seq
         - `preserve_causation: bool = True` — never remove events referenced by causation_id from retained events

       - Async function `compact_journal(journal: EventJournal, run_id: str, policy: RetentionPolicy, snapshot_store: SnapshotStore | None = None) -> int`:
         - Step 1: Read all events for the run into a list: `events = [e async for e in journal.read_from(run_id)]`
         - Step 2: If `len(events) <= policy.keep_last_n`, return 0 (nothing to compact)
         - Step 3: Determine the snapshot boundary. If `snapshot_store` is not None, get `latest = await snapshot_store.latest(run_id)`. If latest exists, `snapshot_seq = latest.event_seq`. Else `snapshot_seq = 0`.
         - Step 4: Build the "must keep" set of event indices:
           - Always keep events with seq > (len(events) - policy.keep_last_n) — the last N
           - If `policy.keep_after_snapshot` and snapshot_seq > 0: keep all events with seq > snapshot_seq
           - If `policy.preserve_causation`: for each kept event, if it has a `causation_id`, find the event with matching `event_id` and add it to the keep set. Repeat until no new events added (transitive closure).
         - Step 5: Filter events to only those in the keep set
         - Step 6: Rewrite the journal file atomically:
           - Get the run path via `journal._get_run_path(run_id)`
           - Write retained events to a temp file (same dir, `.tmp` suffix)
           - Each line: `json.dumps(event_to_dict(event), sort_keys=True) + "\n"`
           - fsync the temp file
           - Atomic rename over the original
         - Step 7: Clear the journal's seq cache for this run_id: `journal._seq_cache.pop(run_id, None)`
         - Step 8: Return `original_count - len(retained_events)`

       - Function `should_compact(journal: EventJournal, run_id: str, policy: RetentionPolicy) -> bool`:
         - Async function that checks if the event count exceeds `policy.max_events`
         - Uses `journal.get_seq(run_id)` as a proxy for event count

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Disk -> SnapshotStore | Snapshot JSON files may be corrupted or tampered |
| Compaction rewrite | Atomic rewrite must not lose data on crash |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | Snapshot JSON on disk | mitigate | SHA-256 integrity hash computed on save, validated on load. Mismatch triggers rebuild from journal. |
| T-01-06 | Denial of Service | Compaction crash mid-write | mitigate | Atomic temp-file + rename pattern. If crash occurs before rename, original file intact. |
| T-01-07 | Tampering | Journal file modified between read and compact | accept | Single-process design; async lock in EventJournal prevents concurrent writes. Multi-process not supported. |
| T-01-08 | Denial of Service | Unbounded causation chain traversal | mitigate | Causation closure is bounded by total event count in journal (finite). No external input controls chain depth. |
</threat_model>
